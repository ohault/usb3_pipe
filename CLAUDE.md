# Project Memory (ohault/usb3_pipe fork)

Context for Claude sessions working on this fork. The general rules are in [AGENTS.md](AGENTS.md) and
[CONTRIBUTING.md](CONTRIBUTING.md) (tests, coding style, commits, hardware safety), which follow LiteX's
[LiteX for AI Agents](https://github.com/enjoy-digital/litex/blob/master/doc/wiki/LiteX-for-AI-Agents.md):
read that page first for LiteX itself (repository map, `--build --no-compile`, `litex_sim`,
`litex_server`/`RemoteClient`, LiteScope, the `litex_mcp` server, the agent skills in LiteX
`doc/agent/skills/`).

## LiteX Projects We Work On

- **USB3-PIPE** (this repository, fork of [enjoy-digital/usb3_pipe](https://github.com/enjoy-digital/usb3_pipe)):
  USB 3.2 Gen 1x2 (2x5Gbps, two lanes) on the LiteX Acorn Baseboard Mini + SQRL Acorn CLE-215+
  (Artix7 GTP), following [issue #140](https://github.com/enjoy-digital/usb3_pipe/issues/140).
- **LiteX Acorn Baseboard Mini** ([enjoy-digital/litex-acorn-baseboard](https://github.com/enjoy-digital/litex-acorn-baseboard)):
  two SFP cages (SFP-0 = J3, closest to the M.2; SFP-1 = J8, closest to the SATA), FTDI on USB-C J7
  (FT2232H on the user's boards, FT4232H on other revisions: JTAG channel A, UART channel B;
  `bench/acorn_ftdi.py`), J10 Pico-EZmate to the Acorn JTAG, power on USB-C J9.
- LiteX, Migen, LiteICLink, LiteX-Boards: dependencies (LiteX `master`); fixes needed there go
  upstream (see AGENTS.md "Contribute back").

## Branches

- `usb3.2-gen1-x2`: Gen 1x2 work (was `claude/usb3-pipe-proposal-vn9kxn`, upstream PR #152, closed

## Gen 1x2 Status

- Done in simulation (`sim.py --lanes 2`, `test/test_phy.py` `TestPHYX2`): Gen 1x2 to U0 with PRBS
  Link-Layer stand-ins, TX lanes lockstep (Logical Idle striped), single lane fallback (Gen 1x1 on
  Lane 0, `sink_x1`/`source_x1`), SuperSpeed partner fallback, lanes swap (Configuration Lane
  detection, `--lanes-crossed`), deskew on the first COM words after a gap, SuperSpeedPlus Link
  Layer/Device Core at Gen 1x2 (`USB3PHYX2Link`, `sim.py --lanes 2 --lanes-core`, `TestPHYX2Core`;
  `bench/acorn.py --lanes 2 --lanes-core`), Gen 1x1 fallback on the Configuration Lane; scripted USB
  host in gateware for the two boards Device Core test (`--role host --lanes-core`,
  `usb3_lanes.py script`).
- Hardware available (user): two Acorn Minis + CLE-215+ and two SFP DAC cables (no SFP2USB adapter,
  no breakout, no Gen 1x2 host yet): tests 1-10 of doc/gen1x2-hardware-validation.md.
- Hardware (2026-11-08, user's NUC with Vivado 2023.2 at ~/tools/Xilinx/Vivado/2023.2, boards on
  FTDI locations 1-3 = Host, 1-5 = Device): Gen 1x2 PHY validated (PRBS, lanes swap, fallback,
  unplug, 20/20 bitstream loads good after the Recovery on a lane realignment in U0); Device Core
  with the scripted host open (62-85% of the runs done, build dependent: follows the Host lanes
  realignments in U0, not the code; Hot Reset before each run removed the `lgood`/`hp_seq` Device
  Recoveries, `pending_hp` remain; the Host realignments in U0 are a consequence: the Device leaves
  U0 on Hot Reset handshakes/Recovery.Idle not converging, then Polling.LFPS):
  [results](doc/gen1x2-hardware-validation.md#results-two-boards-2026-11-08). Test ~20 loads per
  change (`bench/acorn_ftdi.py` load/server per board): a single good load proves nothing, and
  compare two builds of the same source before crediting a change (A/B in its own git worktree,
  check `build_info.json`/`csr.csv` of a kept bitstream: an earlier build may hold uncommitted code).
- Next: the Device Core build
  with a USB 3 host through the SFP2USB adapter/the breakout, then a Gen 1x2 host
  ([doc/gen2-x2-roadmap.md](doc/gen2-x2-roadmap.md): throughput; any host packet placement done in
  simulation, `LanesPacketAligner`, `sim.py --lanes-tx-shift`).

## Environment Notes (Claude Code cloud sessions)

- No Vivado: elaborate (`test/test_targets.py` `elaborate()`), never claim a timing result.
- `pip` installs from git and `litex_setup.py` may be refused: the preinstalled PyPI migen (0.9.2)
  cannot simulate `SyncFIFO` memories (about 78 tests fail identically on `master`: compare the
  failure lists with an upstream worktree before blaming a change).
- `sim.py` needs `pythondata_misc_tapcfg` (only for the LiteX sim Ethernet modules): a local stub
  package on `PYTHONPATH` (header + functions returning -1) is enough.
- Remote branch deletions are refused by the session git proxy: the user deletes/renames branches.
